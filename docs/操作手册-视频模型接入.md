## 二、前端开通流程（管理员后台）

### 准备工作

1. **获取上游 API key**（每家做一次）：
   - 在厂商官网注册账号、完成实名 / 充值
   - 在控制台创建 API key（有些厂商叫"AccessKey + SecretKey"，参考下文"特殊认证"小节）
   - 把 key 保存到 1Password / 公司密码管理器，**不要明文塞 IM**

2. **打开管理员后台**：`https://api.aitracenex.com/console`（SG）或 CN 后台地址，登录管理员账号

### 步骤 1：创建渠道（Channel）

后台路径：**渠道管理 → 添加渠道**

| 字段 | 怎么填 |
|---|---|
| **类型** | 下拉选对应厂商（如 "Kling"、"Vidu"、"DoubaoVideo" 等）|
| **名称** | 给运营自己看的备注，例如 `kling-prod-1`、`vidu-backup` |
| **分组** | 现有分组（如 `default`）或新建一个独立分组（如 `video-only`，避免和文本模型混计费）|
| **密钥（API Key）** | 厂商给的 token；多 key 用换行分隔可启用轮询 |
| **代理 / Base URL** | 留空走默认；如果走自建中转改这里。**Vertex AI 的 region 通过模型名后缀自动识别，无需改**|
| **模型** | 复制本手册第一节"主要模型"那列里的模型名（**完全一致**），多模型用英文逗号分隔 |
| **测试模型** | 选一个最便宜的模型用来跑健康检查（避免"测试一次烧 ¥2"）|

> ⚠️ **特殊认证小节**：
> - **阿里万相 / 即梦**：API key 字段填 `AccessKey:SecretKey`（用英文冒号拼接），系统会按 SigV4 风格签名
> - **Vertex AI**：API key 字段填 service account JSON 文件**整体内容（一行 base64 或多行 JSON 都可）**，需要 `aiplatform.endpoints.predict` 权限
> - **Gemini API（不是 Vertex）**：直接填 Google AI Studio 给的 `AIza...` 字符串
> - **Kling**：早期是 AccessKey + SecretKey 拼接；2026 之后官方有了 v2 token，直接填 token
> - **MiniMax**：填 group_id 和 api_key，格式为 `groupId|apiKey`（管道符分隔）

保存。系统会立即调用厂商 `/health` 或一个最小请求探活；成功 → 渠道状态变绿；失败 → 看红字提示，常见是 key 错或没充值。

### 步骤 2：配置模型价格（Model Price）

后台路径：**运营设置 → 模型倍率 → 模型价格**

视频模型**不按 token 计费**，必须用**按次计费**或**按秒倍率**。两种思路：

#### 方案 A：固定每秒单价（推荐起步）

例：`kling-v2-master` 用户每秒 ¥0.50，平台按 0.7 折给运营，则填：

| key | value | 含义 |
|---|---|---|
| `model_price` 中加 | `kling-v2-master: 0.5` | 用户每秒 ¥0.50 |
| `model_ratio` 中加 | `kling-v2-master: 0.7` | 真实成本 = 0.7 × 用户价（用于内部毛利对账，不影响用户）|

用户提交"5 秒视频" → 预扣 ¥2.50 → 完成后实际扣 ¥2.50（如果上游也确认 5 秒）

#### 方案 B：按档位定价（更精细）

如果厂商不同分辨率/时长有阶梯价（Kling、Veo、Sora 都这样），用 `pkg/billingexpr`（阶梯计费表达式）：

```
input.duration <= 5 && input.resolution == "720p" : 0.30 * input.duration
input.duration <= 5 && input.resolution == "1080p" : 0.50 * input.duration
input.duration > 5 : 0.50 * input.duration
```

后台 → 模型价格 → 选择"动态计费 / 阶梯计费"，把表达式贴进去。

> **跨币种注意**：`model_price` 默认单位是 `quota_per_unit`（一般是 ¥1 = 500000 quota）。检查后台"运营设置 → 通用 → 货币"，确保用户看到的单位和你预期一致（CN 站默认 ¥/RMB，SG 站可设 USD）。

### 步骤 3：分组配置（Group Ratio）

如果你想给 VIP / 内部测试用户更便宜的视频价：

后台路径：**运营设置 → 分组倍率**

| 分组 | 倍率 | 说明 |
|---|---|---|
| `default` | 1.0 | 普通用户 |
| `vip` | 0.8 | VIP 八折 |
| `internal` | 0.0 | 公司内部用，不计费 |

> **不要给视频做 0.0 分组并放出去**，0 元提交会被脚本拿去刷上游。`internal` 分组要绑定特定 token，用 `Token Group Ratio` 限制。

### 步骤 4：发个测试请求验证

在后台**调试 / Playground** 页（或自己用 curl）：

```bash
curl -X POST https://api.aitracenex.com/v1/video/generations \
  -H "Authorization: Bearer sk-你的token" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kling-v1",
    "prompt": "A red panda sliding down a snowy mountain, cinematic 4k",
    "duration": 5
  }'
```

返回 `{"task_id": "abc-123", "status": "submitted", ...}` → ✅ 成功提交，剩下交给后台轮询。

查询任务状态：
```bash
curl https://api.aitracenex.com/v1/video/generations/abc-123 \
  -H "Authorization: Bearer sk-你的token"
```

`status` 会从 `submitted` → `in_progress` → `success`（带 `video_url`）或 `failure`（带 `fail_reason`）。

### 步骤 5：阿里万相参数怎么传给客户

TraceNex 对外只暴露统一视频任务协议：`POST /v1/video/generations` 或 OpenAI-like 的 `POST /v1/videos`。客户**不要**直接使用 DashScope 原生路径 `/api/v1/services/aigc/video-generation/video-synthesis` 调 TraceNex；原生路径里的 `input` / `parameters` 结构由 Ali adaptor 在网关内部生成。

`wan2.6-r2v` / `wan2.6-r2v-flash` 推荐用顶层字段传参考素材和常用参数：

```bash
curl -X POST https://api.aitracenex.com/v1/video/generations \
  -H "Authorization: Bearer sk-你的token" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "wan2.6-r2v-flash",
    "prompt": "character1 坐在窗边演奏民谣，character2 走过来交谈",
    "reference_urls": [
      "https://example.com/character1.mp4",
      "https://example.com/character2.png"
    ],
    "size": "1280*720",
    "duration": 10,
    "audio": true,
    "shot_type": "multi",
    "watermark": false
  }'
```

字段对应关系：

| TraceNex 字段 | 阿里 DashScope 字段 | 说明 |
|---|---|---|
| `prompt` | `input.prompt` | 必填，提示词 |
| `reference_urls` | `input.reference_urls` | `wan2.6-r2v*` 参考图片/视频 URL 数组 |
| `media` | `input.media` | `wan2.7-r2v*` 的新协议形态，元素含 `type` / `url` / `reference_voice` |
| `size` | `parameters.size` | `wan2.6-r2v*` 用具体尺寸，如 `1280*720` / `1920*1080`；也可传 `720P` / `1080P`，TraceNex 会映射 |
| `duration` / `seconds` | `parameters.duration` | 生成时长，单位秒 |
| `audio` | `parameters.audio` | `wan2.6-r2v-flash` 是否生成有声视频 |
| `shot_type` | `parameters.shot_type` | `single` / `multi` |
| `watermark` | `parameters.watermark` | 是否添加水印 |

如果阿里新增参数而 TraceNex 顶层字段还没支持，客户可以用 `metadata` 透传原生 `input` / `parameters`：

```json
{
  "model": "wan2.6-r2v",
  "prompt": "character1 一边喝奶茶，一边随着音乐跳舞",
  "metadata": {
    "input": {
      "reference_urls": ["https://example.com/role.mp4"]
    },
    "parameters": {
      "size": "1280*720",
      "duration": 5,
      "shot_type": "multi"
    }
  }
}
```

优先级规则：顶层字段是产品推荐格式，存在时会覆盖 `metadata` 中对应的阿里原生字段；没有顶层字段时，`metadata.input.reference_urls` / `metadata.input.media` 会原样保留并发送给阿里。

## 三、常见坑点（运营必读）

### 坑 1：视频生成时间长，前端轮询要做对

**问题**：Kling 生成一个 5s 视频实际要 1-3 分钟；Veo 8s 视频要 2-5 分钟；Sora 更慢。

**正确做法**：
- 客户端**不要每秒查一次** `GET /v1/video/generations/{task_id}` —— 命中限流就被 429。建议客户端按"5s 起步、指数退避到 30s"去查
- 后台已经有内置 polling 池每 15-60s 主动拉一次上游，**用户客户端只是查 TraceNex 自己的 DB**，不会真正打到上游
- 限流策略在 `运营设置 → 限流`，给 `relay_task` 路径设个合理的查询频次

### 坑 2：预扣费 vs 实际扣费不一致

**问题**：上游说"我给你 8 秒，不是你要的 10 秒" → 用户已经预扣了 10 秒的钱。

**TraceNex 的处理**：`AdjustBillingOnSubmit` 会基于上游回包修正；`AdjustBillingOnComplete` 会在任务完成时再修正一次。**多扣的钱会自动退回用户余额**，不用人工干预。

**运营要做的**：
- 准备一份"申诉 SOP"：用户反映扣多了 → 直接看 `用量日志` 里那条 task 的 `quota` 列 vs `record consume log` 里的 `total_quota`，看是否两值不一致 → 如果一致说明是正常扣费，不一致看后台日志会有 `billing adjustment` 字样
- **永远不允许手动改 user_quota 字段**。要返还就走"系统消息 + 充值码"补偿，留下审计痕迹

### 坑 3：上游突然涨价 / 下架模型

**问题**：厂商在没通知的情况下把 `kling-v1` 价格从 ¥0.20/s 改到 ¥0.30/s，TraceNex 还在按 0.20 收用户的钱 → 平台亏。

**TraceNex 的应对**：
- 每周一通过 `scripts/channel-benchmark/py/fy-canary` 跑一次基线对比（参考 `Weekly-upstream-sync-runbook.md`）
- 上游下架旧模型时，渠道会开始返回 4xx，TraceNex 把它标"自动禁用"。运营要在**周报**里检查"过去一周自动禁用的渠道"，及时补 channel
- 价格变更要**手动**改，没有自动同步——这是故意的（避免上游恶意涨价瞬间把平台账户打穿）

### 坑 4：用户用错模型名

**问题**：用户写 `"model": "kling"`（少了版本号）→ 上游 400 错误 → 用户投诉"接口坏了"。

**TraceNex 的应对**：
- 上游返回 400 时 TraceNex 会把错误透传给客户端，**带上 `request_id`**
- 运营拿到投诉的 `request_id` → 后台 `用量日志` 搜 → 看 `model_name` 列就知道用户填的是什么
- 在产品文档（`/docs` 页）里给用户列清楚每个模型的**精确名字 + 价格 + 限制**

### 坑 5：图生视频要传图，但参数怎么传？

**TraceNex 统一用 OpenAI 兼容的 schema**：

```json
{
  "model": "kling-v1",
  "prompt": "the panda starts walking",
  "image": "https://example.com/panda.jpg",      // 单图：图生视频
  "image_tail": "https://example.com/panda2.jpg" // 可选：首尾帧
}
```

- 图片 URL 必须公开可访问（HTTPS；如果有签名 URL，时效要 ≥ 视频生成时长 + 30 分钟）
- 厂商不支持 base64 上传时，TraceNex 会在 4xx 错误里提示
- **Vidu** 支持 `images` 数组（参考图生视频，多张），其他厂商一般只支持单图

### 坑 6：Veo / Sora 走代理还是直连

| 模型 | CN 站 | SG 站 |
|---|---|---|
| Veo (Vertex) | ❌ 必须走代理（Vertex 在 CN 不可达）| ✅ 直连 |
| Veo (Gemini API) | ❌ 必须走代理 | ✅ 直连 |
| Sora | ❌ 必须走代理 | ⚠️ 仍然推荐走代理（OpenAI 区域风控严）|
| Kling / Vidu / Hailuo / Wanx / Doubao / Jimeng | ✅ 直连 | ⚠️ 走代理回国（国内厂商对海外 IP 风控严）|

代理在渠道的 **Base URL** 字段配置（用自建的 https 中转 URL 替换厂商默认 URL）。

### 坑 7：内容审核 / NSFW 拦截

不同厂商的内容审核严格度天差地别：

| 厂商 | 审核严格度 | 拒绝时返回 |
|---|---|---|
| Kling / 即梦 / 万相 / Hailuo | 严（中国法规）| 上游 4xx + 中文 reason |
| Doubao | 严 | 上游 4xx |
| Veo / Sora | 中（OpenAI/Google 政策）| 4xx + 英文 reason |
| Vidu | 中 | 4xx |

**运营要做的**：
- 用户投诉"被拒了" → 90% 是 prompt 触发审核 → 在 `用量日志` 看那条 task 的 `fail_reason`
- 不要在你的产品里宣传"无限制 / 无审核"——会被上游永久封号
- 如果客户群体确实是合规但敏感（医疗、安全研究），优先选 Veo / Sora

### 坑 8：高并发会把上游打死

视频厂商的并发上限远低于文本模型：

| 厂商 | 默认并发上限 | 一旦超过 |
|---|---:|---|
| Kling | 5 | 上游 429，等几分钟 |
| Hailuo | 3 | 上游直接拒 + 长冷却 |
| Veo | 10（按 GCP quota）| 静默降优先级，任务排到几小时后 |
| Sora | 视账户档位 | 排队 |

**运营要做的**：
- 在每个视频渠道开"渠道并发上限"（后台 → 渠道详情 → 高级），保守设置（如 Kling 设 3）
- 如果产品要支撑大流量，**多 channel 灰度负载均衡**：建 2-3 个 Kling 渠道，分别用不同账户的 key，TraceNex 自动轮询

### 坑 9：发版后的回滚窗口

视频任务可能跨多个版本：

- 用户在 v1.7 提交了一个任务
- 几分钟后你 `fab release v1.8`，blue 容器从 v1.7 → v1.8
- 后台 polling 池**继承 v1.8 代码**去查任务状态

**潜在问题**：如果 v1.8 改了视频 adapter 的字段映射，老任务的 polling 可能返回错误状态。

**TraceNex 的应对**：
- 视频 adapter 在 OVERLAY.md 里会标"breaking change"，发版前会做 staging 验证
- 24 小时蓝绿窗口期内如果出现"老任务卡住"，可以 `fab rollback v1.7`，老 polling 走回老代码

## 四、运营周检查清单

每周一花 15 分钟做一遍：

- [ ] **渠道健康**：管理后台 → 渠道，看每个视频渠道的"最近测试时间 / 测试结果"，红的要查
- [ ] **额度水位**：去厂商控制台，看每个 API key 的余额，**< 1000 元 / $200** 立即充值
- [ ] **价格基线**：跑一次 `scripts/channel-benchmark/py/fy-canary audit`，确认上游没偷换模型
- [ ] **失败率**：后台 `用量日志` 筛 `status = failure` 过去 7 天，超过 5% 调查
- [ ] **平均响应时长**：用 Prometheus 看 `channel_benchmark_e2e_seconds{channel,model}` 的 p95，超出 5 分钟的渠道考虑下线
- [ ] **NSFW 拒绝率**：失败原因里 `content_filter / safety` 的比例，超过 20% 检查产品 prompt 模板

## 五、新增不在列表里的厂商

如果运营遇到"客户问能不能接 Pika / Runway / Luma..."：

1. **先看是否有现成 adapter**：`relay/channel/task/<vendor>/`，没有就需要工程
2. 提工单到工程，附上：
   - 厂商 API 文档链接
   - 模型列表 + 计费规则（每秒/每次/分辨率档位）
   - 是否有官方 OpenAI 兼容接口（有的话工作量减半）
   - 公司预计的月调用量（决定优先级）
